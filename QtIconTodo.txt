Qt / Linux App Icon TODO
========================

Objective
---------
Add a proper application icon to the Qt/Linux build so icon identity is consistent
in the window titlebar, task switcher, and desktop launcher contexts.

Scope priority
--------------
- Primary target: Qt/Linux runtime icon wiring in src/Main.cpp and MainWindowQt.
- Secondary target: Linux desktop integration (.desktop + installed icon sizes).

High-level answer
-----------------
Yes, this is straightforward and low risk.
The reliable path is: add a Qt resource collection (.qrc), set icon at
QApplication + QMainWindow level, then add desktop integration assets.

Constraints and guardrails
--------------------------
- GUI/resource changes only; no business/data-layer changes.
- Reuse existing repository icon assets where possible.
- Keep Windows .rc/.ico path unchanged.
- Keep each step independently reversible.


Current known assets and gaps
-----------------------------
- Existing assets:
  - AtlantisMajordomo.svg
  - src/GUI/AtlantisMajordomo_256.png
  - src/GUI/AtlantisMajordomo.ico (Windows-focused)
- Current gaps:
  - No .qrc resource file for Qt icon embedding.
  - No QApplication::setWindowIcon(...) call in Linux main path.
  - No setWindowIcon(...) call in MainWindowQt constructor.
  - No Linux .desktop launcher file in repo.
  - No multi-size PNG icon set for hicolor theme install paths.

Step-gate policy (stability between steps)
------------------------------------------
- Gate 1: Isolated changes
  Only touch files listed for the current step.

- Gate 2: Build checkpoint
  After each major phase (Runtime wiring, Desktop assets), run a user build
  checkpoint before proceeding.

- Gate 3: Runtime checkpoint
  Confirm app opens and icon appears in window/task context before desktop work.

- Gate 4: Desktop checkpoint
  Confirm .desktop launcher resolves icon theme name correctly after install.

- Gate 5: Reversible steps
  Keep each step small so regressions can be reverted independently.
